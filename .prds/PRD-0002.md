# Summary
peephole is a stdio MCP server that lets an agent see and drive a remote desktop over VNC: take
screenshots, click, drag, scroll, type and press key combos. v0.1 targets macOS Screen Sharing
with Apple's own login (username and password, security type 30) and also works with classic VNC
auth and unauthenticated servers.

# Problem
Agents that need to operate a Mac (or any VNC desktop) have no lightweight, credential-safe way to
see the screen and send input. Existing Rust VNC clients either lack Apple's login (vnc-rs) or
are built into a GUI viewer (rv).

# Goals
1. Connect to macOS Screen Sharing with the Mac's username and password, without the legacy VNC
   password; also connect with VNC auth and None.
2. Expose screenshot, input and wait tools that an agent can use from Claude Code via
   `claude mcp add`.
3. Keep credentials out of argv, logs and tool output.
4. Test the protocol on the wire: real-server e2e tests, a mock for type 30, unit tests for the
   math and parsing.

# Technical Approach

```
Claude Code ──stdio MCP──▶ mcp::Peephole (tools) ──▶ session::Handle
                                                      │  framebuffer: Arc<RwLock<Framebuffer>>
                                                      │  frames: watch<u64>, state: watch<State>
                                                      │  input: mpsc<ClientMessage> (None if view-only)
                                                      ▼
                                     session task: dial ▶ rfb::handshake ▶ read loop ◀─▶ VNC server
                                                   (reconnect with backoff; auth failure is terminal)
```

- **`rfb`**: our own client, generic over `AsyncRead + AsyncWrite` so tests drive it over any stream.
  `rfb::handshake` negotiates the version (3.3/3.7/3.8; anything newer answered as 3.8), picks a
  security type from what the server offers and which credentials exist (ARD when there is a
  username and password, then VNC auth with a password, then None), and exchanges
  ClientInit/ServerInit. `rfb::auth` holds the pure crypto (DH with `num-bigint`, `md-5`,
  `aes`, `des`) so unit tests pin it with fixed vectors.
- **Decoding**: we send SetPixelFormat (32bpp, depth 24, little-endian, RGB shifts 0/8/16) and
  SetEncodings (ZRLE, CopyRect, Raw, DesktopSize, ExtendedDesktopSize, LastRect). The
  framebuffer stores RGB8, ready for PNG. ZRLE keeps one `flate2` stream and a reusable output
  buffer for the connection.
- **Session**: one task owns the socket. It requests a full frame, then keeps one incremental
  request outstanding, at most every 100 ms. Each completed update bumps a generation on a `watch`
  channel. A writer task serializes input and update requests. The task dials at the first tool
  call, stops re-arming requests after 30 s without one, and disconnects after 10 minutes.
- **MCP**: `rmcp` macros over stdio. Screen space is the full frame scaled so its long edge is
  `--max-edge` (default 1,568). `screenshot {region?, max_edge?}` crops in screen space and
  scales the crop to fit `max_edge`; the text part states the mapping and the framebuffer scale.
  Input tools take screen-space coordinates and map them to framebuffer pixels.
  `wait_for_change` compares region pixels against a baseline on each new generation.
- **Downscale and PNG**: `fast_image_resize` (a 3456×2234 Retina frame is a large-data
  transform on every screenshot) and `png` with fast compression.
- **Keys**: `cmd+shift+g` parses into modifier keysyms (cmd/super/meta → Super_L, ctrl →
  Control_L, alt/option → Alt_L, shift → Shift_L) plus a named key or a character. `type_text`
  maps characters to keysyms: Latin-1 directly, other Unicode as `0x0100_0000 + codepoint`,
  `\n` and `\t` to Return and Tab.

# Assumptions
- Apple's server answers a 3.8 client the standard way, with type 30 in its list, as
  libvncclient relies on.
- Apple's server honors SetPixelFormat and plain ZRLE.

# Constraints
- `rustvncserver` binds `0.0.0.0:<port>` with no way to pass a listener or read back an ephemeral
  port, so tests use its reverse-connect API into a loopback listener the test owns.
- rustvncserver offers only None and VNC auth, so type 30 is tested against a mock server in the
  test suite.
- ARD caps username and password at 63 bytes each (64-byte fields, NUL-terminated); longer values
  are an error, not a silent truncation.

# References to Code
- `src/rfb/`: protocol client (handshake, auth, messages, decode).
- `src/framebuffer.rs`, `src/screenshot.rs`: pixels, cropping, scaling, PNG.
- `src/session.rs`: the long-lived connection.
- `src/keys.rs`: key combos and keysyms.
- `src/mcp.rs`: the tools. `src/config.rs`: CLI-independent config and credentials.
- `tests/rfb.rs`, `tests/ard.rs`, `tests/e2e.rs`.

# Non-Goals (MVP)
- Tight encoding, VeNCrypt/TLS, clipboard sync, the cursor pseudo-encoding.
- Key or region allowlists beyond `--view-only`.
- Multiple simultaneous connections.
